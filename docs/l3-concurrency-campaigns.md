# L3-4 concurrency campaigns

`riscv2x86.microarchitecture-experiment-contract.v4` adds a versioned `campaignContract` (`riscv2x86.l3-concurrency-campaign.v1`) to the existing L3 experiment runner. Its L3 report v3 carries `campaignObservation` on each platform. The capability resolver accepts the new contract schema only when the registered provider declares it. L2 concurrency evidence remains a prerequisite: its contract identity must match the campaign's `l2ConcurrencyContractIdentity`.

A contract identifies the program, exact member fragments, approved relation and semantic facts, source/target allowed outcomes, forbidden outcomes, protocol invariants, thread roles, initial state, schedule, iteration threshold, independent-run threshold, environment and compilation identities. SB/LB/MP/IRIW/lock/atomic_counter are labels; no comparison rule is inferred from a label. `l3_campaign_semantic_facts_identity` must match independently supplied semantic facts. Target strengthening must explicitly declare its approved target outcome subset and a relation identity matching the parent experiment contract. Source and target observations must account for every iteration, independent run and protocol invariant, and match the actual program artifact/environment identities supplied as `source_program_artifact`, `target_program_artifact`, `l3_source_environment_identity` and `l3_target_environment_identity`. Invalid or missing reports are inconclusive.

The declared criterion controls the conclusion:

- `safety`: an observed forbidden or out-of-relation result or a violated protocol invariant is a failure. Passing means only that no such violation was observed in the recorded finite sample.
- `observed_support`: all required outcomes must be observed on target. Absence is inconclusive even after many runs; it never proves an outcome unreachable. A target observation outside the approved set remains a failure.
- `probability`: requires one independently seeded observation per run, an explicit effect tolerance and confidence level. A conservative simultaneous Hoeffding bound across both platforms and all declared outcomes estimates each probability interval; disjoint intervals outside the tolerance indicate failure, intervals contained within the tolerance permit a **bounded statistical** claim, overlap is inconclusive. Detection power is reported as the probability of missing a declared event of at least `minimumDetectableProbability` in N independent samples, `(1-p)^N`. Correlated runs invalidate these bounds; the provider must substantiate its scheduling and independent-run declaration.

A campaign is counted at most once per `(programId, campaignIdentity)` in the batch result, regardless of threads or member fragments; conflicting results for the same pair cause aggregation to fail closed. Source/target raw outcome counts, independent runs, violations, confidence bounds, detection power and observed limitations appear in the L3 result. No finite campaign proves full cross-ISA memory-model equivalence.

Synthetic regression tests cover protocol violations, forbidden results, strengthening boundaries, absent outcomes, probability bounds, malformed reports, duplicated runs, program-level deduplication and integration with L2 contract evidence. Real experiments require registered source/target campaign producers, a matching L2 concurrency contract, independent execution conditions and artifact/environment bindings; absent producers leave L3 inconclusive.
