# L3-6: registered platform experiments

The v6 microarchitecture experiment contract (`riscv2x86.microarchitecture-experiment-contract.v6`) carries a versioned explicit `riscv2x86.l3-specialized-experiment.v1` contract. A v2 L3 runner configuration supplies an independently registered mechanism map and declared platform capabilities; a v5 report includes the associated per-platform aggregate observation. These versions leave older experiments unchanged.

The contract binds a frontend/proof-produced fragment and semantic profile identity, source and target artifact digests, approved target relation, experimental model (`cache_timing`, `branch_prediction`, `instruction_visibility`, `speculation_probe`, or `custom`), registered **public** mechanism for each platform, approved mechanism and environment identity, observation boundary and aggregate-only data visibility, local clock and cache configuration, warmups, sampling plan and number of independent runs. Each metric predeclares a named platform conclusion, its measurement kind, confidence level, and source and target success thresholds. Labels select experiments only: no instruction, file, function or `fence.i` name is treated as proof of the underlying mechanism or experiment outcome.

A side-channel/speculation dimension can be bound **only by an exact explicit provider** using the v6 contract and a v2 runner. The resolver checks the preregistered profile, approved mechanism map, actual environment/artifact identities and source/target capabilities before selecting a runner. No registered mechanism yields `needs_route`. Missing measurement capability or stale environment/report yields `inconclusive`. The L2 prerequisite alone cannot make L3 verified. Functional fallback likewise carries no specialized L3 conclusion without this separately executed contract. Platform-specific `fence.i` instruction visibility, cache flush and branch prediction studies must each register a mechanism; ordinary memory fence validators do not cover them.

The producer reports aggregate hits and independent trials only; raw sensitive data export is forbidden by the declared observation boundary. A Wilson interval is computed independently on each platform. The source experimental conclusion must reproduce. An interval entirely above the prespecified platform threshold supports that platform's conclusion; an interval wholly below it contradicts the conclusion; overlap is inconclusive. Target contradiction after a supported source conclusion is a bounded experimental `failed`, not a proof of cross-ISA hardware mismatch. The resulting claim is `registered-platform-experiment-only`, with explicit nonclaims for cross-ISA hardware equality and identical cache or timing parameters. Different platforms may have different preregistered thresholds. Independent-run and capture-boundary attestations are only as reliable as the registered external experiment producer; synthetic tests do not establish real leakage or hardware properties.

Batch aggregation counts at most one experiment per `(programId, experimentIdentity)`. Synthetic tests cover missing explicit routes, stale contracts, absent environment capability, invalid boundary, incomplete results, uncertain thresholds, source non-reproduction, target contradiction and distinct program-level sampling. To make a real claim, register a controlled source/target producer, actual mechanism approval and environment bindings, then archive its raw experimental aggregates and calibration alongside the L3 report.
