# L3-3 attributed traces

The v3 experiment contract adds `traceContract` (`riscv2x86.l3-attributed-trace-contract.v1`). The L3 v2 platform report adds `logicalTrace` and `machineTrace`. The existing v1/v2 contract/report protocol is unchanged; it does **not** substantiate the new two-layer attribution claim. A provider explicitly declares support for the v3 contract schema in its versioned configuration.

`logicalTrace.events` is a dynamic, ordered list, not a map keyed by source effect. Each visit has a unique event ID, source effect ID, zero-based execution order, predecessors referring to earlier visits, and an object-relative memory payload or control outcome. Repeated visits remain separate. Objects have declared size and minimum alignment, tied to the L2 authority identity and artifact fragment identity. Bare machine pointers, inferred object IDs, and undocumented event kinds are rejected. The comparator checks source and target event order, repetition, offset, width, access direction, atomicity, ordering and control outcome. A complete mismatch is `failed`; malformed or missing evidence is `inconclusive`.

`machineTrace.events` identifies a bounded binary region, compilation settings, entry, observer executable and capture proof. Every machine effect in the region is either attributed to a logical event or excluded under an *exact event ID and kind* entry in the side-specific region contract. An excluded spill or helper access requires an independent proof verifier to approve the capture region and exclusion entry. The evaluator verifies both compiled binary file digests and observer executable digests; the proof verifier binary digest is included in final evidence. Unverified boundaries or exclusions are `inconclusive`. An additional valid logical write or a valid but unmatched machine effect is `failed`. No general rule silently removes stack, prologue or helper events.

The L3 runner requires `l3_source_binary_path`, `l3_target_binary_path`, `l3_attribution_proof_verifier(side, region, exclusion_or_none)`, `l3_attribution_proof_verifier_binary_path` and `l3_attribution_proof_verifier_binary_digest` for v3 contracts. A real provider must supply these from its validated instrumentation and independent proof system. The test suite uses *synthetic* reports/verifier callbacks and demonstrates protocol gating only. Until source and target instrumenters and an actual proof verifier are registered, real runs must remain inconclusive; a valid contract alone does not imply L3 verification. Per-platform timing or cache effects remain outside this trace equality claim.
