# M2/M3 剩余实现方案与验证性能修订

核查基线：Phase130 远端提交 `0ee40d1b837084ba54633dfe8a9f3853af2b788a`。
本轮分支：`phase131-joint-validation-performance`。

本文是后续覆盖扩展的实施依据。本轮只实施验证性能优化和计时，不声称完成下面尚未实现的语义能力。

## 1. 适用范围与完成定义

已声明支持且满足前提的程序，应完成翻译、真实构建、L0–L3 和独立审计；处于该域内的阻塞是必须修复的问题。
域外程序必须报告具体缺失的证明、调用、组合、后端、执行或审计能力。准确拒绝不等于已经补齐能力。
不以“支持任意 C/汇编/物理微架构”作为可验证的目标。普通内存、设备 I/O、指令流可见性和并发原子性是不同的属性域。

每项扩展交付必须同时包含：编译器权威事实、源/目标语义与 shell 证明、部署调用、实际观察、比较、持久化重放、独立审计、正例和有效反例。
只有注册了机制或通过静态检查，不授予生产完成状态。旧模式必须继续保留自己的 schema、合同和适用前提。

Phase130 已验收的子域：直接无环联合程序；8/16/32/64 位普通整数对象；多个指针视图；分离、同地址及同类型成对对齐重叠布局；共享对象状态及重载；普通批准的 `rw/rw` fence。
这些结论受有限调用样本、私有普通内存和现有外壳前提约束，不是任意布局或并发行为的穷尽证明。

## 3. P0：冻结基线、明确覆盖与诊断

1. 保留 Phase130 的 smoke、6 项生产矩阵和 20 项兼容矩阵，包括源码、提交、编译器、后端、实际轨迹和独立审计。
2. 为每个待扩展域建立 obligation 记录：源事实、证明、调用、部署、观察、比较、重放、审计的状态及首个原因。
3. 将“布局被声明”“布局被抽样执行”“该布局属性已比较”区分开；不得把一种布局的通过传播到其它布局。
4. 新增 schema 时要求 JSON 原生类型、类型敏感结构比较、完整字段身份和往返测试。拒绝重复成员、遗漏、无关证据、布尔/整数混淆及旧证据拼接。
5. 翻译或证明失败仍应产生真实的终态诊断；不得以补造通过的 attempt、authority 或 result 解决缺失归档。

完成条件：每个种子的域归属与阻塞有可核查证据；未执行不会被标为 accepted；代码异常与合法域外拒绝可以区分。

## 4. P1：编译器输入输出角色与值版本

不能仅用裸 Clang JSON 节点位置猜测 GNU asm 的输入/输出分区。现有部分 JSON 不包含可独立确定分区的元数据；需要使用 frontend join 后的权威 operands/constraints。

实施步骤：

1. 在 `compiler_fragment_closure` 之后闭合每个槽的 declaration/expression、input/output/read_write、tied、early-clobber、宽度和类型；不完整则保留具体缺口。
2. 按执行区域顺序分配声明值版本：输入读取旧版本；纯输出建立新版本；read_write 同时读取旧版本和定义新版本。tied 和多槽映射必须保持其约束，不能按名字去重。
3. 用新版本连接消费者。纯输出覆盖不是旧值消费者；最终 return 只能消费到达该位置的最后定义。被覆盖但此前已消费的值不能误标 dead。
4. 更新 `l2_fragment_operand_boundary`、dependency graph、execution authority 及 provider/replay 的版本合同；缺少权威事实时不删除现有歧义拒绝。
5. 版本图须区分 C 载体版本、asm 内部机器寄存器版本和内存状态版本；三者不能混用。

验证：同变量两次纯输出；输出后立即读取；读写再定义；tied/early-clobber；多个输出映射；旧值最后使用与新值返回；错误 kill、错接消费者、改输出角色均须拒绝。
当前直接无环域可以先使用线性 reaching definitions；遇到分支不声称该线性算法已覆盖控制流，后续再接 CFG/合流。

## 5. P2：单 asm 有序多访存效应闭环

建议新增版本化 `memory_effect_program`，复用单访问的类型、扩展和地址事实，不把原来的 `len==1` 改成循环后直接授予证明。

每个效应至少绑定：effectId、源指令/p-code 位置、执行序号、LOAD/STORE、访问宽度、地址项、对象候选、对齐/边界前提、值项、源内存版本和目标内存版本。
表达式需固定载体宽度、符号/零扩展、截断及字节序。程序还需列全寄存器输出、隐式效应、终止前提、clobbers 和未解释效应。

1. 解码所有相关 p-code 操作，构建内部寄存器 SSA/内存状态链；拒绝未解释的 call、异常控制和隐式写，而非跳过。
2. 将编译器 GNU operand 的真实地址与对象绑定投影到每个访问。不同 operand 或 objectId 不是 noalias 证明。
3. 建立源程序符号执行及目标细化证明，正确处理 STORE→alias LOAD、重复覆盖、部分重叠和同址访问。最终内存相同不足以证明完整访问模式相同。
4. 新建或扩展候选、约束推导、plan-specific proof、renderer 和合同注册。目标寄存器、flags、地址求值、tied/early-clobber 必须全部闭合；不得输出未证明的 memcpy 或 C 表达式替代。
5. 联合 spec 将成员从“一个访问”升级为“效应程序”。旧单访问 schema 独立保留，不能把多访问裁剪为第一个事件。
6. harness 真实调用并观察所有对象与可见输出；L2 边界观测和语义重放独立于未插桩 L3。QEMU callback 没有提供的值不得标记为实际测得。
7. 动态事件绑定调用、区域实例、PC/静态效应和动态序号。循环/重试若不在本期证明域则拒绝；一次实际访问也不能重复归给多个静态效应。
8. 比较逐项检查方向、宽度、相对地址、顺序/明确批准的细化、所有输出和非批准写区。若目标合法合并/拆分访问，需要单独的关系证明；默认不允许随意丢弃事件。
9. 独立审计从原始源码、编译器事实、合同、ELF、命令和轨迹重建；要求效应和属性双向完整，无遗漏/重复/无关证据。

正例矩阵：两次 load；两次 store；load-store；store-load；同址/部分重叠/分离；窄宽混合；符号扩展；活跃输出与合法丢弃；多个参数位置。
反例矩阵：错地址/方向/宽度/顺序；遗漏/多余事件；只保留最终值的伪等价；无效对齐/越界；少一个输出；shell/约束被改；持久化字段被替换。
完成条件：单 asm 与多个 asm 的每个效应都进入同一次调用状态链，完整 L0–L3 和独立审计通过，且上述反例有效失败。

## 6. P3：合法布局与调用覆盖

1. 将 allocation、view、typed element、可访问字节范围、对象生命周期、对齐、初始化和实际指针关系表示为调用合同。
2. 对三个及以上指针生成明确的合法联合布局：全部分离、多视图同址、部分重叠链、嵌套区间及边界相接。采用规范化布局身份减少对称重复，不按种子名字生成布局。
3. 在允许类型范围内证明布局有效；跨类型别名、字符视图、signed/unsigned 对应类型、restrict、const、volatile、atomic 必须各自有规则。不能用同宽度替代 C 有效类型判断。
4. 使布局覆盖预算独立于值组合预算。先满足每个声明必测布局至少一次，再按策略增加边界值；不足预算应报告未覆盖布局，不能以普通 verified 暗示已全覆盖。
5. 所有 view 必须从同一实际 allocation 派生；相邻对象不能靠整数地址伪造别名。共享存储更新一次后投影全部视图，检查交叠字节一致性及保护区。
6. 多参数和多输出必须统一在编译器调用合同中表达。32 字节自动对象是 harness 前提，不是对任意用户指针容量的证明。

验证至少包含三/四指针、多视图重叠、布局数大于原默认样本数、零/末端偏移、合法边界相接、非法对齐/容量/类型、伪造分离地址、遗漏一个 view。

## 7. P4：一般地址、值与返回表达式

复用 `compiler_expression`、`compiler_expression_evaluation`、`compiler_memory_signature`，增加实际被 proof/renderer/harness 消费的类型化求值合同。

首期范围：可证明无副作用的对象内仿射地址、整数转换、位运算和合法算术；逐类加入，不一次开放所有 AST 节点。
合同须绑定基对象、索引单位、字节偏移、表达式树、类型和源值版本、求值次数/阶段、结果值域及前提。

必须证明：

- 指针运算仍在合法对象域内；one-past 不解引用；实际访问大小、边界和对齐均成立。
- 有符号溢出、非法移位、除零、不确定求值和未初始化输入不被当作正常种子通过。
- 输出 lvalue 的地址及求值次数保持一致；输入表达式不可因 renderer 展开而重复求值。
- GNU constraint 与实际 C 类型转换、访问宽度、寄存器载体宽度、返回类型分别正确，不因同宽度而省略转换。
- 数值/指针转换有明确 ABI 与语言前提；不把复杂表达式退化为基声明再比较。

验证：`p+i`、数组索引、负偏移合法窗口、地址和标量参数重排、signed/unsigned 转换、返回窄化/扩展、可观察多个结果；副作用、越界和语义不明确表达式必须准确拒绝。
所有表达式值应来源于真实调用或明确标识的规格重放，两者不得混称。

## 8. P5：其它普通 fence 的联合观察

1. 在 source model 中以显式 predecessor/successor 掩码表达普通 R/W 顺序，列全所需 ordered pairs；同步记录 compiler barrier 与硬件合同。
2. 根据精确源合同建立目标 refinement：目标有序关系覆盖源义务只是必要条件，仍要确认 API/时序/功能适用性。是否允许加强必须由声明的等价策略决定，并明确记录 exact/strengthened。
3. 同步更新 candidate、constraint、proof、renderer、registry、L2 ordering 及 L3 spec；不得把所有 fence 写成 RW/RW 后宣称精确一致。
4. ELF/机器码归因应辨别实际目标机制、完整执行和区域边界；不得仅按“存在一条 fence”授予全部属性。
5. 同一次调用保留访存-fence-访存的真实事件。事件次序、机制与批准合同分别核验；单线程顺序轨迹不证明物理重排被排除。
6. 后端增加每种机制的正校准及 no-op、缺失、错误掩码/机制等负校准；所有新校准都参加身份绑定、重放和独立审计。

先实施普通 R/W 子集。TSO 或其它扩展形式按其 ISA 合同分别证明，不从名称推断。I/O 和 fence.i 不混入普通域。
完成条件：每个声明 fence 域都有源/目标证明、真实机制、上下文、有效反例及独立审计；`physicalMemoryOrderMeasured` 不因静态细化而改为 true。

## 9. P6：环境路线及整体清算

环境路线需要补充的是目标实验合同，而不是重复采集普通 smoke：

- 指令流：本 hart 还是跨 hart 发布；代码生成/修改方式；页权限；允许的 runtime API；发布和完成确认机制；观察哪个执行结果。
- I/O：设备或模拟设备型号、MMIO 地址域和映射、设备端顺序语义、完成确认及可观察结果。
- 如果要求并发或物理微架构保证：相应硬件/模型和测量方法必须独立设计，不从用户态 QEMU 普通内存轨迹推导。

明确合同后接通已有 `instruction_stream_sync_contracts`、local environment/mechanism 与真实执行路线。环境缺失应保持未完成；不能自动降级成普通内存验证。

清算时对每个域保留：适用前提、源码/提交/工具链、正负矩阵、合同/证明身份、实际观察、独立审计、未覆盖义务及覆盖账本。
域内阻塞应修复；域外缺口需具体解释，不用“程序复杂”代替原因。有限抽样与静态普遍证明应在论文和报告中分别陈述。

## 10. 性能原因、已实施优化和保留工作

已从代码确认的重复工作：

1. `l3_joint_backend.validate` 每次遍历 12 项校准；每项 `check_calibration` 都重新编译校准程序并比较执行映像，还会验证基础后端、工具链和文件依赖。
2. 旧的新捕获路径完整后端验证 6 次：入口一次、双端 capture 各前后一次、group replay 一次。每个后续成员读取已有 group 时又先验证一次、replay 再一次。
3. `l3_joint_deployment.validate` 的每次重放都会重建双端部署，包含编译器重新检查、编译、汇编和链接。
4. `automatic_l2_joint` 与 `l2_joint_replay` 仍对成员产生/独立重建整程序语义观测；测试还会额外调用独立审计和篡改拒绝检查。
5. pytest 矩阵按当前命令串行执行。增加 timeout 不会使正常执行变快。

本轮实际优化：

- 新捕获使用仅限该操作的 `BackendValidationSession`：完整初检一次，内部复用后端结果，退出前完整无缓存复查一次。退出复查失败不返回/发布捕获组。
- `capture` 默认调用仍保持独立前后校验；只有显式传入操作会话及原后端路径才能复用，并严格核对内存中的后端内容。
- 已有 group 的成员移除 replay 前多余的完整后端检查；replay 本身仍完整验证。
- 不缓存部署重建、实际轨迹、成员证明或比较；独立审计没有生产会话，重新检查原始证据。

因此，对 m 个成员的正常 L3 路线（不含外层配置加载/额外审计），完整联合后端校验调用由 `6+2*(m-1)` 变成 `2+(m-1)`。
这只是调用次数，不是端到端加速比。每项校准仍真实重建，每个成员的部署重放和独立审计仍存在。不得用该公式声称测试时间必定减少固定百分比。

新增可选 `RV2X86_VALIDATION_TIMING=/absolute/path.jsonl`，记录 translation.command、L2 成员/独立重放、L3 后端/校准/捕获/部署重建/group replay/成员/审计的包含时间及父子关系。
`inspect_validation_timing.py` 输出调用数、异常次数、包含时间和扣除直接子跨度后的时间；跨进程时间不能相加解释为整体 wall time。
`returned` 只表示函数返回，返回 inconclusive 也可能是 true；计时不授予语义批准。
不设置环境变量则不写记录。诊断写入失败在 stderr 报告，不替换原验证异常。正常译码、证明和观察数据不写入计时日志。

后续性能工作须依据真实计时再排序：将成员级整程序 L2/部署重建迁移为操作内共享、每成员独立投影，需完整依赖集合和强制末尾复查；不能简单在跨运行字典里记住通过结果。
