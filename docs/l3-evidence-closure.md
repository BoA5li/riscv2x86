# L3-7: closed experimental evidence and claim scopes

The versioned `l3-dimension-result.v1` records each required property by
`propertyId`, dimension and evidence unit. Its content identity covers the
requirement, intent profile, approved experiment contract, translation and
compiled artifact digests, source/target report and environment identities,
execution identity, comparison evidence and L0/L1/L2 prerequisite identities.
The runner obtains reports from actual source/target command responses; a
provider's bare `verified` token cannot replace these records.
Parsed source and target report bodies accompany the closed result so their
content digests can be checked again by the provider wrapper, batch report and
paper aggregation. Report export must follow the approved observation boundary.

`l3-fragment-result.v1` closes the exact required property set. A missing
property or uncovered effect is inconclusive, a complete contradiction is
failed, and every verified property with the correct scope is verified. The
program result uses required fragment IDs, ignores nonrequired members, and
counts unique execution identities once. A missing required member prevents a
verified program conclusion.

The `microarch` plan needs verified L0/L1, typed L2 architectural scope and
an architectural translation artifact. An explicit `microarch_diagnostic` plan
requires a functional fallback, L2 approved functional relation scope and the
functional comparison policy. Its `target_experiment_diagnostic` conclusions
are preserved separately from `architectural_intent`; writeback admission and
the paper's formal L3 numerator do not accept a diagnostic as architectural.
Selecting the ordinary `microarch` profile for a fallback remains invalid.

Existing v1 experimental contracts have no authoritative requirement identity
and therefore cannot create a closed formal paper L3 claim. Reports or contract
files that change during execution, malformed/partial reports, and stale typed
L2 fragment evidence return inconclusive. A logical trace or aggregate
measurement only proves the properties declared in its approved contract; it
does not prove cross-ISA cache or timing equivalence.

The tests cover missing properties or members, repeated execution identities,
unapproved effects, changed content with a stale hash, report digest mismatch,
wrong L2 claim scope and functional diagnostic boundaries. These tests use
synthetic controlled reports; real hardware conclusions still require an
independent producer and a registered experimental mechanism.
